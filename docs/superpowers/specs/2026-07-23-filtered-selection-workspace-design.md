# filtered 页面已选素材工作台设计

## 背景

`apply_verdicts.py` 生成静态的 `filtered.html`。页面会根据 `script_matches.json` 和 `filler_matches.json` 给 AI 匹配素材输出初始 `checked`，但前端的 checkbox `change` 事件目前只调用 `refresh()` 更新计数，没有保存人工勾选或取消勾选。因此刷新或重新打开页面后，选择状态会退回生成时的 AI 默认值。

本次把 `filtered.html` 从一次性选择页补齐为可持续浏览的已选素材工作台：人工选择跨刷新、重开和重新出页保留；右上角可切换到跨分区的连续已选网格；F1 像浏览器“查找下一个”一样逐条定位已选素材。

## 目标

1. 人工勾选和取消勾选均持久化到当前 `BROLL_RES`，刷新、关闭后重开、下载服务换端口后仍能恢复。
2. 重新运行 `apply_verdicts.py` 后，已有素材沿用人工状态，新出现的素材沿用新页面的 AI 默认勾选状态。
3. 右上角提供“展示已选（N）”切换按钮，把 KEEP、REVIEW、DROP、中性垫片等分区中的已选卡片聚合到一个连续网格。
4. F1 从当前浏览位置开始定位下一条已选素材，之后逐条循环，并提供明显的当前项高亮。
5. 保持现有下载、批量清洗、三态全选、悬浮预览、主题池和 filler 池行为不变。

## 非目标

- 不增加账号、云端数据库或跨设备同步。
- 不改变 AI 自动匹配、判分、去重或下载清洗数据契约。
- 不新增“上一条”快捷键、搜索框、排序器或编辑素材元数据。
- 不使用 Playwright、前端框架或后台常驻新服务。

## 方案选择

采用“结果目录状态文件为主、浏览器本地存储为备用”的轻方案。

- 主状态写入 `BROLL_RES/selection_state.json`，由已有 `download_server.py` 暴露读写端点。状态与结果目录绑定，不受浏览器端口变化影响。
- `localStorage` 同步保存同一份状态；下载服务未启动或短暂不可用时仍可在相同浏览器 origin 内恢复和继续选择。
- 不采用纯 `localStorage`，因为 `http.server` 端口变化会改变 origin。
- 不直接改写 `filtered.html` 的 `checked` 属性，因为下一次运行 `apply_verdicts.py` 会覆盖文件，也无法清楚区分 AI 默认和人工选择。

## 稳定身份与状态模型

`apply_verdicts.py` 已有与 `download_server.py` 对齐的 `stable_id(page, url)`。每个素材 checkbox 新增 `data-id="<stable_id>"`，持久状态只引用该 ID，不依赖 DOM 顺序、标题或分区。

`selection_state.json` 使用以下结构：

```json
{
  "version": 1,
  "revision": 7,
  "known_ids": ["BV...", "xhs_..."],
  "selected_ids": ["BV..."],
  "updated_at": "2026-07-23T12:34:56+08:00"
}
```

- `known_ids` 表示用户上次保存状态时页面中已见过的素材。
- `selected_ids` 表示这些已见素材中当前勾选的子集。
- `revision` 从 1 开始；每次用户改变选择或页面把新素材纳入已知集合时加 1。浏览器备用和服务端快照冲突时选择较大的 revision，同 revision 选择服务端快照。
- 首次打开且没有状态文件时，以 HTML 中 AI 输出的 `checked` 为初值，并立即保存。
- 再次打开时：已存在于 `known_ids` 的素材严格恢复人工状态；当前页面中新出现、尚不在 `known_ids` 的素材保留 HTML 中的 AI 默认状态。
- 当前页面已消失的旧 ID 从新快照中裁掉，避免状态文件无限增长。
- 空的 `selected_ids` 是有效状态，必须与“尚未初始化”区分，确保“全部人工取消”刷新后不会重新勾回。

## 下载服务接口

在现有 loopback 服务中增加：

- `GET /selection`：读取当前 `RES/selection_state.json`。文件不存在时返回 `initialized: false` 和空集合；存在且合法时返回 `initialized: true` 及规范化状态。
- `POST /selection`：接收完整快照，校验版本、非负整数 revision 与字符串 ID 数组，在固定路径原子写入后返回保存数量。每个数组最多 50,000 项，每个 ID 长度为 1–200 个字符，`selected_ids` 必须是 `known_ids` 的子集。

写入使用临时文件加 `os.replace`，并用进程内锁保护，避免全选或快速连点产生半文件。前端保存按顺序串行提交，避免较早请求晚到而覆盖较新选择。

接口继续沿用现有 CORS 处理；任何读写错误都返回明确 JSON 错误，不能影响下载、预览和清洗端点。

## 页面初始化与保存流程

1. 页面读取 `./.dlport`，确定当前结果目录对应的下载服务地址。
2. 记录 DOM 中所有 checkbox 的 AI 默认状态。
3. 读取与本结果目录对应的 `localStorage` 备用快照，先做同步恢复，避免页面明显跳动。
4. 请求 `GET /selection`：服务端和本地快照都存在时使用 revision 较大者，同 revision 使用服务端；服务端未初始化时使用当前合并后的页面状态创建首份快照；请求失败时继续使用本地备用状态。若本地快照更新，恢复连接后的下一次保存会把它同步到服务端。
5. 每次单项 checkbox 或分区三态全选改变后，同步更新计数、卡片选中样式、`localStorage`，再把完整快照按顺序提交到 `POST /selection`。
6. 保存失败时保留页面选择和本地备用，不回滚用户操作；在 header 日志区域给出轻量提示，下一次变化继续重试。

`localStorage` 的 key 由生成页面时嵌入的结果目录命名空间哈希构成，避免同一 origin 下不同选题互相覆盖。

## “展示已选”聚合视图

header 右侧在下载和清洗按钮之前增加 `展示已选（N）` 按钮。

正常视图中，各素材卡片仍在原 KEEP、REVIEW、DROP 和 filler 分区。进入聚合视图时：

1. 页面显示一个 `selectedWorkspace` 区域和单一响应式网格。
2. 为每张卡片保留原位置锚点，把已选卡片的原 DOM 节点移动到连续网格，而不是复制卡片。
3. 隐藏原分区，按钮文案变为“返回全部素材（N）”。
4. 因为移动的是原节点，checkbox、悬浮预览、下载/清洗 payload 和数据属性始终只有一份。
5. 在聚合视图取消勾选时，该卡片立即回到其原位置并从聚合网格消失，状态同步保存；聚合区为空时显示“当前没有已选素材”。
6. 返回全部素材时，所有卡片按锚点精确还原到原分区和原顺序。

分区三态全选只在正常视图使用；聚合视图隐藏原分区标题和全选控件，不增加新的“全部取消”按钮，避免误操作。

## F1 定位行为

页面监听未带修饰键的 `keydown`，当 `event.key === "F1"` 时阻止浏览器默认帮助行为并执行定位。

- 没有当前定位项时，从当前视口顶部向下寻找第一张已选卡片；下方没有则循环到页面中的第一张。
- 已有当前定位项时，定位到当前视图顺序中的下一张已选卡片；到末尾后循环回第一张。
- 正常视图遇到位于关闭的 `<details>` 中的素材时，先展开其所有祖先 `<details>`。
- 使用 `scrollIntoView({behavior: "smooth", block: "center"})` 居中滚动。
- 当前卡片保留醒目的高对比描边和轻微脉冲效果，直到下一次 F1、该项被取消或视图切换；同时短暂显示“已选 X / N”。
- 聚合视图按连续网格的 DOM 顺序定位。
- 如果没有已选素材，header 给出“当前没有已选素材”，页面不滚动。
- 不实现 Shift+F1 或上一条快捷键。

macOS 是否把实体 F1 交给浏览器取决于系统键盘设置；系统将功能键用于亮度等功能时，用户需要按 `fn + F1`。这是操作系统边界，页面无法拦截未送达浏览器的按键。

## 与现有未提交改动的兼容

当前 `apply_verdicts.py` 工作区包含尚未提交的 filler 池、搜索词面板和 payload 字段改动。本次只在这些改动之上追加：

- 所有主题与 filler checkbox 都生成 `data-id`。
- 状态统计必须覆盖现有 `keep`、`review`、`drop`、`filler`，同时也要正确处理 filler-drop 中的可选卡片。
- 移动卡片不能改变 `data-pool`、`data-from-script`、`data-script` 或 `data-persona`。
- 不回退、不重写上述既有未提交改动。

## 错误处理

- 状态文件不存在：按首次初始化处理。
- 状态文件损坏或字段非法：服务端返回错误；页面保留 AI 默认或本地备用状态并提示，不能把损坏内容静默覆盖为空。
- 服务未启动：本次会话仍可选择和聚合，使用 `localStorage`；下载与清洗沿用现有连接失败提示。
- 状态中包含当前页面不存在的 ID：忽略并在下一次保存时裁掉。
- 当前定位项被取消：清除高亮；下一次 F1 从当前视口重新寻找。
- 聚合视图切换时停止当前悬浮播放，避免移动 DOM 后残留播放器。

## 测试策略

1. 新增纯 Python 状态测试：不存在、合法往返、空选择、损坏文件、规范化和原子覆盖。
2. 新增 HTML 生成回归测试：每个 checkbox 有稳定 `data-id`；header 包含聚合按钮；脚本包含服务端读写、备用存储、视图切换和 F1 入口。
3. 用小 fixture 运行真实 `apply_verdicts.py`，覆盖 AI 默认选中、人工状态模型合并所需的 DOM 契约，以及主题和 filler 卡片。
4. 运行现有全部 `tests/test_*.py`，确认下载/清洗字段、script matches、filler 和判分行为不回退。
5. 启动临时结果页和下载服务做浏览器交互验证：人工增删选择后刷新、关闭重开、聚合/还原、聚合视图取消、正常视图和聚合视图连续按 F1、末尾循环。

## 验收标准

- 人工勾选和取消后刷新，选择列表完全一致。
- 关闭页面并重新打开，或下载服务换端口，选择列表仍一致。
- 重新出页后，旧素材恢复人工状态，新素材采用 AI 默认状态。
- “展示已选（N）”展示跨全部分区的连续网格；返回后卡片顺序不变。
- 聚合视图中取消素材后立即消失，下载/清洗数量同步变化，刷新后仍保持取消。
- F1 从当前浏览位置开始逐条跳转，高亮明显，到末尾循环，折叠区自动展开。
- 没有已选素材、服务暂不可用或状态文件损坏时，页面不崩溃且给出可理解提示。
- 现有测试全部通过，新增状态与页面契约测试通过。
