# Pexels 验收页批量下载设计

## 目标

让 `results_romeo_ai_education_20260723_pexels/filtered.html` 与主素材页一样支持：

1. 保留当前 10 条自动勾选结果；
2. 点击“下载选中”后选择目录；
3. 将所选 Pexels 视频逐条保存到本地；
4. 页面持续显示成功、跳过和失败进度；
5. 继续彻底禁用批量清洗。

## 第一性原理

批量下载只需要三个事实：

- 页面知道用户选中了哪些素材；
- 每条素材携带一个可下载的官方 MP4 地址；
- 本机端点能校验地址、保存文件并回传结果。

本批 `harvest_pexels.json` 已保存 10 条已选素材对应的
`https://videos.pexels.com/...mp4` 直链，因此无需重新搜索、打开浏览器抓取或引入新的下载框架。

## 最小数据流

1. 以 `harvest_pexels.json` 的 `page -> direct_url` 映射为真源，将 `direct_url`
   补回本批 Pexels 页面下载负载。
2. 页面恢复现有“下载选中”按钮；按钮仍复用既有 `/pickdir`、`/download`
   和 NDJSON 进度处理。
3. `download_server.py` 将 `platform=Pexels` 或 Pexels 主机识别为 `pexels`，
   不再错误回落到 B 站。
4. Pexels 下载器只接受：
   - `https`；
   - 主机名严格等于 `videos.pexels.com`；
   - 路径以 `.mp4` 结尾或响应为视频内容。
5. 下载结果继续走既有命名、幂等跳过、单条失败继续和 `_manifest.jsonl` 台账。
6. 为 Pexels 结果目录单独启动一个 `download_server.py`，让该页面自己的
   `.dlport` 指向正确端口。

## 安全与边界

- 不调用 `/clean`，页面继续隐藏并拦截清洗按钮。
- Pexels 下载端点使用不可达的本地清洗地址，避免误操作创建外部清洗任务。
- 不自动开始下载；仅在用户点击“下载选中”后执行。
- 不修改主素材页的 50 条视频和 30 张小红书图片选择。
- 不重跑素材搜索、相关性打分或自动勾选。

## 错误处理

- 缺少 `direct_url`：该条失败并给出明确提示，其余条目继续。
- 非官方域名、非 HTTPS：拒绝下载。
- HTTP 错误、超时或文件过小：该条失败并记录原因。
- 已存在同名有效文件：按现有逻辑记为跳过。
- 下载完成后仍自动打开目标文件夹。

## 验证

实现遵循测试先行：

1. 先写失败测试，证明当前 Pexels 会被误判为 B 站且没有下载器；
2. 验证 Pexels 平台识别、文件名、官方域名白名单；
3. 用本地 HTTP 测试替身验证成功、失败和非法域名，不下载真实视频；
4. 验证页面 10 条仍被勾选、下载按钮可见、负载含 10 个官方直链；
5. 验证清洗按钮仍隐藏且点击保护仍在；
6. 启动 Pexels 独立端点，验证 `.dlport`、`/ping` 和页面同源发现均正确。

## 完成标准

刷新 Pexels 验收页后，用户可以点击“下载选中”，选择目录并批量下载当前
10 条已选视频；页面显示逐条进度，任何单条失败不阻断整批，且不会产生清洗任务。
