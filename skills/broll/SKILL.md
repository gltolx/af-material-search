# /broll — 多平台素材搜割 + 关联度三色筛选

项目根:`{{BROLL_HOME}}`。给一批口播稿,按下面 8 步跑。**复用已有脚本,别重写逻辑。** 细节见 repo 的 `PLAN-B.md` / `SCORING.md` / `ARCHITECTURE.md`(§13 平台分工、§14 查询姿势)。

## 0. 先同步 + 自检(必做,顺序别反)
1. **自动同步最新代码**:`bash {{BROLL_HOME}}/selfupdate.sh` —— ff-only 拉 origin,每次用技能都跑(代码常驻最新,免手动 git pull);离线/脏树/非 git 仓自动跳过不阻塞,merge 成功会顺带重新盖章各客户端的 SKILL.md。
2. **自检**:`bash {{BROLL_HOME}}/preflight.sh`(它会自愈 yt-dlp 毒行等环境坑)。**红灯按三路决策树处置,别一刀切"修或问"**:
   - **(a) 缺失/坏类(抖音 venv / yt-dlp / ffmpeg / PIL 等环境组件)→ 自动补装,不问用户**:先 `bash {{BROLL_HOME}}/setup.sh`(幂等,已装的跳过),个别依赖(如 PIL)可 `pip3 install --user <pkg>`(**稳态禁 uv tool install/uvx**;新依赖一律 pip3 install --user)→ 补完**重跑 preflight**;**仍红才停下报告**。
   - **(b) 登录态类(B站/YT 缺 Chrome cookie、小红书未登录)→ 停下提醒用户去 Chrome 登录,不自动降级**。这是与验证码并列的**唯二合规打断点**之一(见 `captcha_playbook.md` 顶部):B站/YT 高清靠 web 登录态(同 YT 360p 的真因是没登录,不是纯 IP),缺 cookie 直接暂停并说明要在 Chrome 登录 B站/YouTube 后重试,**不偷偷降清晰度**。
   - **(c) 仅 Command Line Tools 未装(全新 Mac,python3/pip/git 全是桩)→ 真停**:提示 `xcode-select --install`,装完重跑。其余红灯不属于真停范畴。
   **全新机/换客户端**:先 `bash {{BROLL_HOME}}/install.sh`(装技能进 Claude/Codex + 装环境 + 自检,幂等)。

## 运行时适配层(Claude Code + Codex)
| 运行时 | 浏览器能力 | 小红书/抖音收割方式 | 前置动作 |
|---|---|---|---|
| Claude Code(本机版) | Claude-in-Chrome 的 navigate/javascript_tool 等 | 直接使用 `browser_harvest_snippets.md` 的 DOM 抓取片段,经 `writer_server.py` 落盘到 `BROLL_RES/xhs_raw.json` / `dy_raw.json` | Chrome 登录小红书/抖音/B站/YouTube;收割前自起 writer_server |
| Codex(本机版) | chrome-devtools MCP 的 navigate/evaluate/screenshot | 使用同源 DOM 抓取逻辑,按 `browser_harvest_codex.md` 由 evaluate 返回 JSON,再写同名 raw 文件;下游脚本完全共用 | 先 `bash {{BROLL_HOME}}/codex_chrome.sh`;MCP 必须 attach `http://127.0.0.1:9222`,健康检查是 `/json/version`,不要打开裸 `http://127.0.0.1:9222/` 当页面;给用户看的永远是 `http.server` 的 `filtered.html` |

不支持 claude.ai 网页、Claude 桌面云端、或任何碰不到本机 Chrome/下载目录的远程运行时。两条运行时只在前台浏览器收割适配层不同;`harvest_net.py`、`merge_scored.py`、打分、出页、下载、清洗、入库全部共用。

## 8 步流水线
1. **接稿 + 解析 `results/scripts.json`**:稿子放 `topics/{选题}/` 或直接读。**逐条解析出 `[{script_id,persona,name,text,words}]`**——稿件正文一般自带标题与人设号名称,自己判:缺标题则总结一个短标题,缺人设号则 `persona` 留空。`words`=正文字数(决定该稿可配素材数上限)。
2. **出 `results/relevance_spec.json`**(每选题一次):AI 读稿提炼视觉概念 → 概念词 + 负面词 + 平台分工 + 三色阈值,**外加四组查询词**:`bili_queries`(数组)、`yt_queries`(`[["kw",N],...]`)给 `harvest_net.py` 读;`xhs_queries`/`douyin_queries`(数组)给前台浏览器收割用。查询/概念**必带年代/意图锚点**(上世纪/八九十年代 · 老式/复古/怀旧/年代感 · 回忆杀/那些年/童年)+ 平台行话(**描述≠召回**)。换选题只改这一处。**务必填 `core_subjects`**(本批不可妥协的核心视觉主体,尤其品牌/产品本体,如 `["格力","空调"]`)。**铁律:品牌/产品本体【必须】进 queries,不能只写进 concepts(concepts 只用于召回后打分,不召回);任何"排除/不搜"的约束必须能引出处,引不出不准用。** 见记忆 [[broll-core-subject-must-be-in-queries]]。
2.5. **核心主体自愈(收割前必跑,绝不停机)**:`BROLL_RES=<dir> python3 {{BROLL_HOME}}/autoheal_queries.py`(system python3)。它无条件自查——稿件正文高频(≥80%篇)或 `core_subjects` 声明的核心主体若在四组 queries **0 覆盖** → **自动补 2~4 条该主体的语境化查询词**(写进独立字段 `spec.autoheal_added`,**绝不改原 queries 数组**),记 `autoheal.log` + 打印摘要,继续不停。**收割读"合并词"**:`harvest_net.py` 已自动 `base ∪ autoheal_added` 读 bili(启动会再幂等自愈一次);**前台浏览器收割 douyin/xhs 时,AI 把 `autoheal_added.douyin`/`.xhs` 的词并进一起搜**。补的词会显示在 `filtered.html`「🔎本批搜索词」按钮(自动补带橙色角标)。`score_candidates.py` 每批必跑,会红灯报"品牌/产品核心主体仍未覆盖"兜底。
3. **四平台【并行】收割 → `results/scored.json`**(`[{platform,title,url,page,cover}]`):**三股并行,挂钟≈max 而非 sum**(实测 6 步全干净≈6-7 分,对比串行≈32 分 ~5×)。
   - **收割前自检自起 writer_server(落盘桥,不问用户)**:`lsof -iTCP -sTCP:LISTEN -P 2>/dev/null | grep -q ':8799' || (BROLL_RES=<dir> python3 writer_server.py &)`(run_in_background)。**端口自适应**:8799 被占自动顺延,实际端口写 `BROLL_RES/.writerport`、stdout 打 `WRITER_PORT=<n>`;收割 JS 从 `.writerport` 读端口拼 `fetch`,**别硬编码 8799**(见 `browser_harvest_snippets.md`)。**多会话并行收割务必带 SID + 各用独立 BROLL_RES**(见下「多会话并行」小节)。
   - **后台流(Bash,无浏览器,run_in_background):** `BROLL_RES=<dir> python3 harvest_net.py` —— B站 ∥ YouTube 双线程(ThreadPoolExecutor),~30s,写 `harvest_net.json`,被前台吸收。
   - **前台浏览器流(本会话内单 Chrome,小红书/抖音串行但快;同一会话的子 agent 不能并发驱动第二个 Chrome——这是会话内约束。跨会话多开见下「多会话并行」小节:同窗口不同标签页 + 会话隔离可并行)。按上面的「运行时适配层」选择:Claude Code 走 `browser_harvest_snippets.md` + writer_server;Codex 先 `bash {{BROLL_HOME}}/codex_chrome.sh`,再走 `browser_harvest_codex.md` + chrome-devtools MCP。**
     - **小红书** DOM 抓(CLI `xhs` 已被韩国出口 IP captcha 焊死,改走浏览器=国内节点):navigate `xiaohongshu.com/search_result?keyword=KW&type=video` → JS `scrollTo` 到底 ×3 懒加载 → 抓 `a[href*="/explore/"]` 的 note id(**`id.split('').join('.')` 点分隔躲工具对长串的屏蔽**)+ 封面 `img.src` + `.title` 文本;localStorage(键带 SID)跨同源页累计,末尾**`fetch` POST 到本地 `writer_server.py`(loopback,端口从 `.writerport` 读)落盘**(`navigator.clipboard` 在重页会卡死,别用)。~9 词≈230 条。
     - **抖音** DOM 抓(**废弃方向键+iesdouyin,改 DOM-scrape,~10×快且稳**):navigate `douyin.com/search/KW?type=video` → 等 render(轮询 `a[href*="/video/"]`.length>0,~5s)→ **以 anchor 为真源**抓 `a[href*="/video/"]` 的 19 位 id(点分隔),再从最近容器取封面/标题;新版 DOM 中 `.search-result-card` 可能不再包住 anchor,只用它会抓空。**`url` 留空,无水印解析延后到【选片后只解被选中的】**(绕开 iesdouyin 对 KR 的 ~80 次限流)。**节奏:每词 `random.uniform(8,12)` 秒随机停(见下「节奏铁律」,绝不固定 6/8;有并发会话再加码)避反爬**;同 writer_server 桥落盘。~6 词≈170 条。
     - **前台收割日志必须落盘**:`_codex_dy_log.json` / `_codex_xhs_log.json` 记 `{kw,anchors,rows,added,total,blocked,err}`。某词 `anchors=0` 只代表该词无结果或 DOM 未给,不等于登录掉线;只有 `blocked=true`/明确验证码才合规暂停。日志是判断“补词还是等人”的依据。
     - **Codex 适配**:没有 Claude-in-Chrome 时,小红书/抖音走 **`browser_harvest_codex.md`**:**同一套收割 JS**(就上面两段),只是用 **chrome-devtools MCP 的 `navigate`+`evaluate`** 驱动、数据靠 **`evaluate` 直接返回**(实测 token 不被屏蔽)而非 writer_server;落盘文件名/字段 schema 与 Claude Code 轨**完全一致**,`merge_scored.py` 不分运行时、下游零改动。
   - **合并**:`python3 merge_scored.py`(读 harvest_net/xhs/douyin 三文件 → scored.json,canon 去重)。
   - **浏览器 JS 直接套 `browser_harvest_snippets.md`**(抖音/小红书 DOM 抓取 + writer 桥的实测片段,别现推)。Claude Code 轨端口从 `.writerport` 读;Codex 轨按 `browser_harvest_codex.md` 把 evaluate 返回值写入同名 raw 文件。收割 JS 的 `dyAll_<SID>`/`xhsAll_<SID>` localStorage 键必须带 SID(并行时),落盘文件名固定 `dy_raw.json`/`xhs_raw.json`,靠独立 `BROLL_RES` 隔离。
   - 隔离重跑:三脚本+score/apply 都认 `BROLL_RES=<abs dir>` 环境变量(默认 `results/`),非破坏性跑进 `results_xxx/`。
4. **预过滤**:`python3 score_candidates.py`(**system python3**)→ `prefilter.json`(kill 负面 / need_enrich 小红书空标题 / need_llm)。
5. **语义判分(AI 亲自,标题为主+封面辅)**:只对 need_llm 桶分片(~50/批,量大可拉子 agent 并行)按 `SCORING.md` rubric 给 `[{idx,score,scene,era,reason,need_cover}]` → 写 `results/scores_part*.json`。**不是关键词累加**(那样误杀误留);小红书空标题靠封面/`xhs read` 正文,**别判 0**。**二段式降噪**:第一段保留强主题(一晚一度电/APF/抽真空/压缩机/电费/核心主体),第二段把促销/推荐/维修/招聘/汽车空调/泛教程降到 review/drop;品牌名单独命中不能进 keep。**外加 R1 人物主体判定**:每条多给 `person_primary∈{none,partial,dominant}`(none=物/景/事件主体,partial=人群/背景/手部,dominant=单人说话头/正脸占屏过半)+ `need_frames`(封面看不准时置 true)+ `eye_contact`(正面半身/全身人脸且眼睛 ≥2/3 帧锁定盯镜头→apply_verdicts 硬丢 drop;抽不到帧则不置 true)。封面看不准的(`need_frames=true`)跑 `python3 extract_early_frames.py` 下开头6秒抽帧到 `covers_frames/<idx>_f*.jpg`,**AI 自己 Read 这些帧图判定后回填 `person_primary`/分数,不问用户**(看帧判定是 AI 本职,不打断)。降分由 apply_verdicts 按 `relevance_spec.json.person_penalty` 确定性执行;**>`max_duration_sec`** 的会被预过滤/判决弃,口径以 spec 为准。详见 `SCORING.md`。
6. **判决+去重+封面+出页**:`python3 apply_verdicts.py`(**system python3,要 PIL**)→ 三色 + ID去重 + 封面本地化 + pHash 近重去重 → `results/filtered.html`(出页含**卡片时长角标**[读 scored.json 的 `duration`]、**header 右上「展示已选」连续聚合网格+下载区**、每区**一个三态全选框**、人工选择按 stable_id 写 `selection_state.json` **跨刷新/重开保存**[localStorage 备用]、**F1 从当前视口定位下一条已选并循环**、**悬浮自动播放挂点**、**下前预检标灰**[读 `dl_precheck.json`,见 6a])。时长靠 duration 字段:收割时自带(B站/YT/抖音)或 `backfill_duration.py` 补(小红书);旧批次没 duration 先跑它。**出页 JS 不再把 :8788 烘焙进 HTML**——运行期同源 `fetch('./.dlport',{cache:'no-store'})` 读 download_server 实际端口(读不到回落 8788),`/download`、`/preview`、`/clean`、`/selection`、`/precheck`、`/cancel_clean`、`/pickdir`、`/ping` 全用读到的端口拼。
6a. **下前预检(出页前插一步,把高置信不可下项标灰提示)**:① 先起 download_server(带 MATCLEAN env,见第 7 步同款命令,run_in_background);确认 LISTEN 后从旁车读端口:`DLP=$(cat <dir>/.dlport 2>/dev/null || echo 8788)`。② `curl -s "http://127.0.0.1:$DLP/precheck"`(只对 keep 区跑)→ 产 `results/dl_precheck.json`(键=stable_id,值 `{ok,reason,level∈ok|warn|fail}`)。**新原则:预检只做"高置信、极低请求量"判断,绝不对刚收割完的平台猛探**——
   - **小红书预检零网络探测**(关键):**图文**查本地 `xhs_imgs.json` 映射(有 `imgs`→ok、无 `imgs`→fail「带imageList重收割」)、**视频**默认 `ok`「yt-dlp可下,下载时实测(预检不主动探避免风控)」、**无类型映射**→`warn`。**绝不对 xhs 发任何网络请求**(无 yt-dlp/`resolve_preview`/SSR)——因为探测=下载同源请求,小红书风控敏感,刚收割完(常 300+ 条)立刻逐条猛探**必触 300013「访问频繁」**→ 后续探测全失败 → 把**能下的**视频也假阴性标「无法下载」。**实测小红书视频 yt-dlp 能下**(一条 27MB 下成、`yt-dlp -j` 解出 1280x720)。
   - **B站/YT/抖音按平台抽样**(不是逐条):每平台从 keep 区取**最多 2 条**做真探测(B站带 cookie / YT 用 `yt-dlp -j --simulate`、抖音用 `dy_resolve`),得该平台"样本结论"应用到该平台 keep 区**全部条目**(同平台同出口一致)。**抽样全失败只标该平台 `warn`「抽样未通过,下载实测」(不判死 fail,避免重蹈假阴性)**;抽样通过→该平台全 `ok`。总探测数 ≤6,**低并发(≤3)**。
   - **永远别对刚收割完的平台立刻猛探**;页面「⚠无法下载」只在**高置信**(如图文缺映射)时给,**宁可不报也别假阴性**。
   ③ **再跑一遍 `python3 apply_verdicts.py`**,出页据 `dl_precheck.json` 把 `level==fail` 的卡标灰红角标「⚠无法下载」**(只提示、不禁选——仍可勾选、匹配到稿的仍自动勾)**,header 汇总无法下原因。**文件/键缺失=视为可下**(向后兼容,不阻塞)。**注意**:小红书**视频**笔记真实可下性留到选片后抓 masterURL 实测(见 6b);出页预检对 xhs 视频只给 `ok`(默认可下),绝不预判 fail。
6b. **逐稿匹配 + 自动选片(R3/R4)**:读 `results/scripts.json` + `results/verdicts.json`(keep + 高分 review 候选),**逐稿做语义匹配**,产出 `results/script_matches.json`:`{script_id:{persona,name,words,matched:[{idx,stable_id,reason,score}]}}`。**配额(按口播稿总数 N 分档,稿越多每稿越少)**:**N≥10 → 2~5 条/稿**(常态);**5≤N≤9 → 4~6 条/稿**;**N<5 → 5~7 条/稿**(少稿多配)。边界:N=10 归 ≥10 档(2~5)。同档内长稿(正文>500字)取偏上限。**不硬凑**(优质匹配明显不足 / <2 条记欠匹配,**只在汇报里提示补搜,不停下问用户**——欠匹配不是打断点)。**主题硬约束 + 多样性**:抽真空稿优先抽真空/APF稿优先 APF/虚标/压缩机稿优先压缩机/1赫兹/外机;同稿最多 1 条纯话术/同标签口播,其余优先实测、电表、外机、压缩机、安装、工况画面;育儿/家庭人设要主动找孩子/卧室/夜间/家庭开空调视觉锚点。**竞品风险不硬杀但要标记**:命中 美的/三菱/海信/海尔/大金/小米/TCL 等,`reason` 写明“竞品/对照风险”,避免正向背书误用。**独占**:每个素材只挂最适配的一条稿(`idx` 不重复出现)。写完 **重跑 `python3 apply_verdicts.py`**——它吃 `script_matches.json` 重渲 `filtered.html`:匹配卡片自动勾选 + 卡片显示 `👤人设 ｜ 📄稿名`,checkbox 带 `data-script/data-persona`。
   - **匹配理由要结构化**:不要只截标题;`reason` 至少含 `why_this_script`(为何适配该稿)、`visual_type`(实测/电表/外机/压缩机/安装/口播/图文)、`risk`(竞品/人物口播/促销/维修/时长未知)。清洗前对自动勾选的抖音/小红书补时长或轻量探测;时长未知可看页,但不应无提示直入清洗。
   - **两轮勾选 + 小红书视频可下性实测(选片后做,量小)**:
     - **第一轮(理想匹配)**:逐稿匹配按"假设都可下"选最佳(即上面的常规匹配,不受出页预检 warn 影响)。
     - **小红书视频 masterURL 实测**:第一轮选完后,对【选中的】小红书**视频**笔记,**逐条用浏览器打开详情页**(navigate→等渲染),从 `window.__INITIAL_STATE__` 的 `note`(`noteDetailMap`→`note`→`video.media.stream` 的 `h264/h265/av1[].masterUrl` 或 `backupUrls`)取 **masterURL**,回填进 `results/xhs_imgs.json` 对应 note 的 **`video_url`** 字段(download_server 的 `dl_xiaohongshu` 见到 `video_url` 即 requests 直拉 CDN,优先于 yt-dlp/SSR)。**务必限速(≥数秒/条)防 300013「访问频繁」风控**;量小(通常几~十几条)。
     - **抓到** = 可下;**抓不到** = 该视频确实下不了 → 出页标「⚠无法下载」(只提示、不禁选)。
     - **第二轮(补充勾选)**:对抓不到/确实下不了的小红书视频,从该稿的 keep/review 候选池里**补等量替补**(再回填到 `script_matches.json` 或直接在页面勾),保证每篇稿仍有足额可下素材。

## 中性垫片池(filler)——增量平行轨(用户要"干净中性空镜垫片"时才启用)
**定位:** 在主题池之外【并联】一个抓"口播稿提到的、与主题无关的干净中性空镜"(天空/云/车流/键盘/翻书/咖啡/脚步/窗光/雨滴/人群剪影…)做转场垫片的池子。**铁律:绝不影响主题池的搜索/召回/排序/打分/筛选/勾选/补勾选**——代码已在 `score_candidates.py`(据 `src_pool` 分桶 `need_llm_filler`)和 `apply_verdicts.py`(加载后第一步按 `pool` 劈出 filler,主题轨只见 theme 候选)做了物理隔离,且有冒烟测试证明"有/无 filler 时主题 verdicts.json 字节一致"。**不启用(spec 无 `filler` 或 `filler.enable=false`)时全链路与今天逐字节一致。**

启用时,在 8 步流水线上叠加这几步(其余步骤照常):
1. **派生(扩展 step 2)**:逐稿从**正文里实际提到的中性画面**派生 filler 概念,**全部可追溯到稿句**(不维护固定通用词库)。写进 `relevance_spec.json` 的 `filler` 对象:`enable:true`、`queries.douyin/.xhs`(只投**抖音+小红书,B站暂不进**;每概念 3~5 变体,带创作者行话锚点 空镜/素材/延时/氛围感/治愈/4K/特写)、`concepts:[{name,from_script,src_sentence}]`。**边界硬规则:filler = 去掉主体后仍成立、换任何选题都不违和的画面;派生词若命中本批 `hard_anchors∪core_subjects` 一律剔除**(别把主题主体当中性垫片)。
2. **收割(扩展 step 3)**:filler **单独一轮收割**(抖音+小红书),产物落 **`harvest_douyin_filler.json`/`harvest_xhs_filler.json`**(`merge_scored.py` 自动标 `src_pool=filler`,同视频跨池 theme 优先)。**小红书放行图文**:搜 `type` 不限 video、**务必带 imageList**(否则图文被 yt-dlp 下成幻灯片 mp4)。节奏照「节奏铁律」(抖音 8~12s 随机)。
3. **判关联度(扩展 step 5,需 LLM)**:对 `prefilter.json` 的 **`need_llm_filler`** 桶,AI **按【标题+封面】判**"这条是不是该稿那句话所指的那类**干净、可剪、无水印/教程/带货**的中性空镜"(**不是**判与主题痛点的关联度)→ 写 **`scores_filler_part*.json`**(与主题 `scores_part*.json` 完全分开,同 schema:`score/scene/reason/person_primary/eye_contact/need_frames`;封面看不准可抽帧)。`apply_verdicts` 的 `verdict_filler` 据此判决:超 `max_dur_sec`(默认25s)弃、`eye_contact` 盯镜头弃、`person_primary=dominant` 弃、按 `filler.plat_thresholds` 三色。
4. **逐稿匹配 + 自动勾选(扩展 step 6b)**:从 judged keep 里**逐稿选 ≤`per_script_cap`(默认6)条** → 写 **`filler_matches.json`**(`{script_id:{name,persona,matched:[{idx,src_sentence}]}}`;**idx 必须与主题 `script_matches.json` 互斥**;**某稿 0 条就报缺,不拿通用空镜补**——`apply_verdicts` 会在页面橙条列出欠匹配稿)。重跑 `apply_verdicts.py` → 页面自动出**「🎞 中性垫片池」区**(按时长升序、命中自动勾选、卡片标 🎞中性｜稿名)。
5. **下载/清洗/入库**:复用现有「下载选中/批量清洗」按钮(filler 卡片带 `data-pool=filler`,payload 自动透传);`build_autorun_selected.py` 让 filler **搭该稿自己的库**(同 source_link/账号/库名)+ 标 `pool=filler`+`from_script`,`autorun_kb.py` 零改动按 source_link 并组入库。**RAG 隔离**:manifest/node2 payload 都带 `pool` 标记,下游可据它对中性垫片降权(避免泛画面稀释主题库检索)。**小红书图文**:node2 图片直传未打通前,图文先只下到本地 + 进 manifest,不投 node2(待 node2 owner 加"非清洗直传"通道)。

## 多会话并行(多开 Claude Code/Codex 同时跑·会话隔离)
**结论(用户拍板④,修正旧"收割不能并行"措辞):收割是 DOM-scrape(JS 注入),同窗口不同标签页 + 复用登录态可并行。** 之前串数据的真凶不是"物理不能并行",而是三处共享态(`localStorage` 的 `dyAll`/`xhsAll` 按域名共享、首词 `setItem([])` 互相清空;单 `writer_server:8799`+共享 `dy_raw/xhs_raw.json` 文件名;共享 `results/`)。靠**会话隔离**全解,无需重框架:
- **① 各用独立 `BROLL_RES`(硬步骤,不是可选)**:每会话 `export BROLL_RES=$PWD/results_<选题>`,scored/verdicts/filtered.html/xhs_imgs/封面 各落各目录,互不覆盖。
- **② SID 化收割态**:收割 JS 的 localStorage 键 `dyAll`/`xhsAll` → `dyAll_<SID>`/`xhsAll_<SID>`(SID = 本会话短串,建议取 BROLL_RES 末段目录名;详见 `browser_harvest_snippets.md` 顶部)。**落盘文件名固定** `dy_raw.json`/`xhs_raw.json`(merge_scored/decode_raw 读固定名),并行隔离靠各自独立 `BROLL_RES`。否则同域两会话会互相清空/混入,且不报错。
- **③ 端口自适应**:`writer_server`/`download_server`/选片页都从默认端口向上顺延找空闲端口、写旁车(`.writerport`/`.dlport`)、出页运行期读真实端口 —— 各会话各起各的、自动错开,**再也不用 kill 别人进程**(kill 正在边下边传的活进程会让 node2 那条永卡 loading,这是唯一的清洗杀手)。
- **剩余真限制(物理约束,别承诺消除)**:验证码/登录的**视觉操作同刻只能解一个**;各会话**只动自己的标签页**(别去点别人的);Claude-in-Chrome 按账号连一个实例。**"一个搜索 + 一个下载"并行最安全**(下载几乎不碰浏览器)。两会话**同时**收割同一平台需各自标签页 + 节奏更克制(撞码概率叠加)。

## 节奏铁律(反爬·随机抖动·用户拍板 2026-06-18)
**所有平台、所有 API 与爬取的节奏一律随机抖动,绝不用固定常数(固定心跳=机器味=撞码)。**
- **抖音**:每次导航/词间 `random.uniform(8,12)` 秒(不是死 8,更不是 6)。`browser_batch` 里 navigate→wait→scrape 的那个 `wait` **就是**词间真实间隔,把它设成 8~12 随机(一个值同时覆盖 ~5s 渲染需求)。
- **小红书 / B站 / YouTube 的一切**——API 调用间隔、搜索词间、滚动懒加载等待、masterURL 逐条实测、下载/重试节奏——都在**原文档规则数值上 ±2s 随机浮动**(原 ~5s→`uniform(3,7)`、原 2s→`uniform(0.5,4)`…),每一拍都随机化,绝不每次同一个值。
- **明文数字规则=硬地板,绝不向下约等于**:随机区间的**下限 ≥ 文档地板**(抖音下限 8);多个时间约束并存时**取 max 再加抖动**。设完节奏参数回核一句"区间下限 ≥ 文档地板?"再开跑。(血泪:曾把 ≥8s/词当渲染延时锚到 ~5s 压成 6s → 撞码。)
- **撞码=合规打断点 ≠ 缩量**:每个平台的词该搜全,撞码就喊用户过码后**继续把该平台的词搜完**,不准擅自缩词或"撞一次就停"(收割量靠多词,见「不够量就扩词」)。

## 坑 → 对策(本会话血泪,必避)
- **抖音(2026-06 改 DOM-scrape)**:搜索页结果**就在 DOM**——以 `a[href*="/video/"]` 为真源取 19 位 id,再从最近容器取封面/标题,**别只依赖 `.search-result-card`**(新版 DOM 它可能不包 anchor → `anchors>0` 但落盘 0)。坑:① 初次结果走 fetch 但在 hook 装好前已发完、`<script id=RENDER_DATA>`(SSR)里无 aweme → **拦截器不稳,别用,DOM 抓最靠谱**;② **导航太快→"点两个相同形状物体"captcha**(我不能代过)→ **每词 `random.uniform(8,12)` 秒随机停(绝不固定 6/8;见「节奏铁律」)**,撞墙喊用户过码后**继续搜完该平台的词**(不缩量);③ 某个 query `anchors=0` 先记日志继续,不自动归因登录态/验证码;④ 无水印 URL **延后到选片**才 `DouyinProcessor('dummy').parse_share_url`(import 是 `.server` 不是 `.processor`),下载 `requests` 带 `Referer: https://www.douyin.com/`(curl 对字节 CDN 报 SSL,禁用)。
- **小红书(2026-06)**:CLI `xhs` 被**韩国出口 IP captcha 焊死**(初次可能过 1 个词,之后持续验证码,退避无效)→ **改走浏览器 DOM 抓**(国内节点);**标题常空** → need_enrich,靠封面判,**别当 0 分杀**。
- **小红书图文笔记下载必须有类型映射(2026-06)**:图文笔记(`type=normal`)要下成**静态图**,download_server 靠 `xhs_imgs.json`(note→`{t,imgs}`)判 `t=="normal"`→下图片。**没这张图就全走 yt-dlp,而 yt-dlp 把图文笔记报成平台自动合成的~15秒幻灯片视频→下成 mp4**(yt-dlp 无法区分图文/视频,实测坐实)。`type`+`imgs` 只来自浏览器收割的 `imageList`(落 `xhs_raw.json`)。**现已收口:`merge_scored.py` 在 `xhs_raw.json` 存在时自动产 `xhs_imgs.json`**(不再单靠 `backfill_xhs_token.py`);收割小红书务必用带 `imageList` 的片段(`browser_harvest_snippets.md`)。下载时若某 xhs 无类型映射,进度流/manifest 会 **`warn` 告警**(图文可能被下成幻灯片 mp4)→ 带 imageList 重收割补图再下。
- **浏览器→磁盘桥**:`navigator.clipboard.writeText` 在重页会**死等卡死**(文档失焦/权限)→ 用 `writer_server.py`(loopback,**端口自适应**:默认 8799 占用顺延,实际端口在 `BROLL_RES/.writerport`;Chrome 免 mixed-content)`fetch` POST 落盘,稳。**收割 JS 从 `.writerport` 读端口拼,别硬编码 8799;localStorage 键/落盘文件名并行时带 SID**(见 `browser_harvest_snippets.md`)。长 id/token 会被工具当 base64/敏感**屏蔽** → 公开 id **点分隔**回传再 Python 去点。
- **验证码(所有平台)→ 见 `captcha_playbook.md`**:**铁律——AI 运行时绝不自动求解/绕过验证码(授权也不行)**;只做 检测→截屏→识别类型→暂停→**交用户秒解**→无损续跑,外加**避免=治本**(各平台节奏/词数配方在手册)。增量落盘 + `_progress.json` 断点续跑,撞码不丢进度、不阻塞 B站/YT 后台轨。
- **B站/YT**:yt-dlp 优先 avc1、要 ffmpeg 合 DASH;**带 `--cookies-from-browser chrome` 能解锁到 1080P**(没 cookie 海外 IP 必 412、且封顶 480P);跑过 agent-reach 会写 `--js-runtimes` 毒行进 yt-dlp config(preflight 已自动剔除)。`scored.json` 把 B站+YT 合并成 `platform="B站/YT"` → 下载按 **URL host** 分流(bilibili.com vs youtube.com),别按 platform 字段。**大视频流抗截断(2026-06 实测坑)**:韩国出口 IP 下 B站/YT 几十 MB 的视频流常被 CDN 掐断(`SSL EOF`/`Did not get any data blocks`,小广告片几 MB 能下完、大片只剩音轨残片 `.fNNN.m4a` → 投 node2 清洗音频必失败)→ `_ytdlp` 已加 `--http-chunk-size 10M`(分块 range 请求,抗截断)+ `_find_output` 排除 `.fNNN.` 中间分片(只认已合并产物,绝不把残留音轨当成片)。
- **下载(第8步,download_server.py)**:**抖音必从 `page` 现解**(verdicts 缓存的 play 链带时效签名会过期);下载端点**必用 douyin venv python**(system py3 无 requests → 抖音/小红书直下会 ImportError);**YT 韩国出口 IP 下 403/只 360p**(硬限,非参数能调,需国内节点)。**agent-reach 不做下载(实测复核坐实,非评审推断)**——一手实跑证据:① `agent-reach --help` 子命令只有 setup/install/configure/doctor/transcribe/...，**无任何 download/get/fetch 动词**,唯一内容动词 transcribe 只产文字稿;它定位白纸黑字"只负责从互联网获取内容"(搜索/正文/字幕)。② 它的 `video.md` 明令**"不要用 yt-dlp 读 B站"**——按它路线反而废掉我们已跑通的 B站 cookie 1080P 姿势。③ 本机后端几乎没装(`opencli`/`bili`/`deno` 全缺,`~/.agent-reach/tools` 空),要用得先装一堆 + 登录。④ 它的 install/setup 走 uv tool + 写回 `--js-runtimes` 毒行(preflight 已专门 sed 剔),**为下载引入它直接违反"稳态禁 uv"铁律**。真正下载还是 yt-dlp/DouyinProcessor(我们已直连),**别为下载引入它**。
- **悬浮自动播放(4人会实测 + 用户调优)**:**小红书+抖音**都走 download_server `GET /preview?page=` 同源 Range 代理喂 `<video>`(小红书 yt-dlp -j 取 CDN;**抖音 DouyinProcessor 现解 play_addr+下游带 Referer**,每条首播烧 1 次 KR 解析额度、缓存后不再解);裸 `<video>` 直连都不行(xhsCDN 不暴露 Content-Range、抖音 302→zjcdn 防盗链无 CORS)。**B站/YT 用官方 iframe**(`player.bilibili.com/player.html?bvid=X&autoplay=1&muted=1&danmaku=0`、`youtube.com/embed/<id>?autoplay=1&mute=1`,**必 muted**;YT embed 在 KR 能用,与下载 403 两码事;DASH 没法 `<video>` 直流,~1s 冷启动固有)。**丝滑(去黑屏闪+慢):封面当底 + player `opacity:0` 盖上 + `<video poster=本地封面>`,`playing`/iframe `load`+600ms 才加 `.ready` 淡入 → 全程显封面绝不黑**;防抖 120ms;全局单例+移开即停。真·秒开(含B站)需预下 360P 小片("方案B",用户暂不要)。
- **时长(duration)易被白名单吞**:`merge_scored.py`/`score_candidates.py` 把记录重建成固定字段,**加 `duration` 必须在 harvest_*/merge_scored/score_candidates 全链路都带**(漏一处则卡片不显时长且无报错);统一存**整数秒**,显示层才转 mm:ss。B站搜索 API 时长是不补零 `M:SS`(分钟可超60,如 `119:46`),必须 `parse_dur` 解析成秒;抖音 `video.duration` 是**毫秒**(÷1000),别取顶层 duration(None)。
